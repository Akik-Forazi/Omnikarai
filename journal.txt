### Bugs Fixed This Session

**1. RSP alignment in fn bodies (codegen.c `aligned_frame`)**
- Old formula added +8 to N, making N%16==8 inside user fn bodies
- After `push rbp`, RSP%16==0, so N must be %16==0
- Fix: removed `N += 8` — now `N = (locals+32+15)&~15`
- Fixed: t05_functions, t05_fact, all recursive calls

**2. Test runner using --beta (tests/run_tests.ps1)**
- `run --beta` mixed stderr traces into stdout, poisoning output matching
- Fix: changed to `run --quiet`

**3. for loop continue target (codegen.c `cg_for_range`)**
- `continue` jumped to loop_top (condition) instead of increment step
- Fix: resolve continue patches to `inc_top` (after body, before increment)
- Also: replaced blind `next_offset -= 24` with `saved_next_off` restore

**4. parse_if_statement eating sibling statements (parser.c)**
- After `if X: break` (no else), `parse_if_statement` consumed DEDENT,
  advanced to next sibling token, block loop advance check ate it
- Fix 1: `if_just_ran = (tok_before == TOKEN_IF)` — skip advance after if stmt
- Fix 2: `parse_if_statement` no longer does `p->indent_depth++`

**5. while/for leaving DEDENT unconsumed (parser.c)**
- `parse_while_statement` and `parse_for_statement` left body's DEDENT for caller
- Outer block loop broke on it, never seeing statements after the while/for
- Fix: both now consume their own DEDENT before returning
- Fixed: NameError for vars defined after while in fn bodies (stress03/05/08/09)

**6. parse_dot_expression rejecting keyword member names (parser.c)**
- `list.set(...)` failed: `set` is TOKEN_SET not TOKEN_IDENT
- Fix: replaced `expect_peek(TOKEN_IDENT)` with `parser_next_token()` + null check

**7. datetime accessors with 0 args (codegen.c)**
- `datetime.year()`, `datetime.month()` etc. called with no argument (stress06)
- Fix: added DT_0ARG macro that auto-calls `datetime.now()` then the accessor

**8. sys.arch() missing (codegen.c)**
- Fix: added as alias for `sys.platform()`

### Architecture Notes (parser token contract)
- `parse_if_statement`: always consumes its body's DEDENT, peeks for elif/else
- `parse_while_statement`: now consumes its body's DEDENT before returning
- `parse_for_statement`: now consumes its body's DEDENT before returning
- `parse_fn_definition`: still leaves DEDENT for caller (codegen handles fn bodies separately)
- `parse_block_statement`: `if_just_ran` flag prevents double-advance after if stmts
- Block loop exits on any DEDENT (simple, relies on compound stmts consuming their own)
